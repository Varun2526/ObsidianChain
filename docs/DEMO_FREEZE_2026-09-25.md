## Revision 2 (same day): clean-start investigator demo

Superseded the first freeze after a review of the demo flow. The first
screens showed the Elliptic++ reference run as if it were existing work, and
an uploaded dataset's alerts could be looked at but never decided on, so the
recorded flow had to switch to reference-run alerts halfway through.

What changed (tag `demo-freeze-2026-09-25-v2`):

- **Uploaded-run alerts are case alerts.** Addressed as
  `<run fingerprint>:<rank>`, previewable before referencing, referenced,
  decided, reported and reviewed like any other; a case bound to its own
  run is current against it (`console/run_alerts.py`,
  `tests/test_run_alert_casework.py`).
- **Graph investigation of the uploaded run.** Explorer run mode with
  inspector, find, filters, full screen, and money-flow paths and reach over
  value edges only (a path through membership or relay links is labelled as
  not a money flow). Case Graph and Network tabs show the uploaded run.
- **Alert detail for uploaded alerts.** Evidence by class, TreeSHAP
  contributions, network propagation with DB-IP countries, money flow
  around the alert.
- **Clean first screens.** Overview no longer shows the reference run; the
  global queue is labelled "Reference alerts"; validation findings are
  visible without expanding details.
- **Demo capture.** `data/samples/demo_capture_synthetic.csv`, generated by
  `scripts/make_demo_capture.py` (seeded, synthetic, keyless addresses).

The Elliptic++ reference data, model and artifacts are unchanged and still
present; they are simply not presented as the investigator's own case.
