## Why not — the Phase 16 preconditions are not yet met

Per the research mandate's own Phase 16 checklist, the sealed holdout is a
**one-time final confirmation**, read only after every development decision
is frozen. As of this document, the following are **not yet frozen**:

| Precondition | Status |
|---|---|
| Candidate pipeline frozen | **No** — exp01 leaves 3 candidates tied (RF/HGB/LightGBM); no single model has been selected |
| Features frozen | **Partially** — Group A/B confirmed necessary; Group C/D's fate is scoped to LightGBM only (`13_red_team_review.md`); the counterparty-history feature lead from `07_error_analysis.md` has not been engineered or tested at all |
| Preprocessing frozen | Yes in practice (`nan_to_num` + `float32`, consistent across every experiment) — not a blocker |
| Model frozen | **No** — see candidate-pipeline row; LightGBM has an evidence-based edge on explainability (`10_explanation_audit.md`) but this has not been treated as a final decision |
| Alert policy frozen | **No** — `09_alert_policy_analysis.md` rejects the current severity-band mechanism outright and proposes but does not implement or test a replacement |
| Explanations frozen | **No** — `10_explanation_audit.md` rejects the current method; TreeSHAP via `pred_contrib` is recommended but not wired into `ps_model.py` |
| Reproducibility verified | Partial — every experiment script is reproducible (fixed seed, logged in `experiments.jsonl`) but no `make test` re-run was performed as part of this program (`01_repo_audit.md` §13, deferred) |
| Manifests verified | v1 manifest read and understood; no v2 manifest exists yet (no v2 model has been trained) |
| Holdout hash verified | Not re-verified in this program; `data/models/ps_native/datasets/manifest.json`'s recorded `test.parquet` hash was read (as metadata only, not the file contents) in `01_repo_audit.md`/`02_data_audit.md` |

**Reading the holdout now would be premature** — it would either measure an
unfinished pipeline (wasting the one-time read on a configuration nobody
will ship) or, worse, create pressure to treat the holdout read as informal
guidance for further development decisions, which is precisely the failure
mode `ml/protocol.py`'s seal mechanism exists to prevent (`HoldoutSealError`
raised at `Fold` construction, not just at use — HANDOFF.md's "folds
reaching the holdout" trap).

## What must happen before Phase 16 can legitimately run

1. Decide the model: given `05_model_comparison.md`'s tie and
   `10_explanation_audit.md`'s LightGBM-specific explainability evidence,
   **LightGBM is the best-evidenced default** among the three tied
   candidates, but this program does not unilaterally declare it "the"
   choice — that is a Phase 17 recommendation, not a Phase 14 fact, and
   still requires the counterparty-history feature question (below) to be
   resolved first, since it could change which features the frozen model
   trains on.
2. Test the counterparty-history feature idea from `07_error_analysis.md`
   (cheapest, highest-value untested lead) — engineer it, run it through
   `protocol.evaluate_candidate` alongside the current feature set, and
   reach a KEEP/REJECT decision under the full 12-fold family protocol
   before freezing the feature set.
3. Confirm exp02's C/D-weak finding on at least one other tied-tier model
   (RF or HGB) per `13_red_team_review.md`'s scope narrowing, before
   deciding whether Groups C/D are dropped from the frozen feature set.
4. Re-derive severity-band thresholds on a properly held-out
   threshold-selection split (never the set the precision is reported
   against) — `09_alert_policy_analysis.md`.
5. Wire TreeSHAP (`pred_contrib`) into the explanation path for whichever
   model is chosen, and re-verify local fidelity on the frozen model
   exactly as `10_explanation_audit.md` did on the exploratory one.
6. Train the actual v2 model artifact under `ml/protocol.py`'s discipline,
   write its manifest (mirroring `data/models/ps_native/v1/manifest.json`'s
   structure), and re-run `make test`.
7. **Only then**, call `protocol.break_seal(reason=...)` with a written
   reason, run one evaluation against `test.parquet`, and report that
   number exactly once.

This document exists to make the non-event explicit and auditable, per
RULE 7 (never hide what wasn't done) — the absence of a holdout number in
this research program is a decision, not an oversight.
